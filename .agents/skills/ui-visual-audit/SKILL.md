# 视觉设计与多模态前置自审规范 (UI Visual Audit)

凡涉及视觉界面、组件样式、海报、流程图或 PDF 排版改动，在向用户交付前**必须执行本规范的渲染截图与 `view_file` 视觉自审闭环**。

## 一、 标准截图视口与环境
使用 Playwright 渲染真实页面并截图（开启 `device_scale_factor=2` 高清采样）：
1. **桌面网页 (`dist_pages/` / `sandbox.html`)**：`1280 × 900`
2. **小程序预览 (`preview_miniprogram.html`)**：`390 × 844`
3. **电商详情页/海报 (`taobao/`)**：宽度 `800px`（按切片或全长截图）
4. **文档流程图 (`README.md` SVG)**：分别在浅色 (`#ffffff`) 与暗色 (`#0d1117`) 背景下截图核验

## 二、 五维全局视觉自检标准（不限于用户指出的问题）
调用 `view_file` 审视截图时，必须逐项排查以下五个维度：
1. **密度与呼吸感**：
   - 桌面端卡片网格单排控制在 **6~7 列**（间距 `≥16px`），移动端单排 **4~5 列**；严禁塞成密恐图标墙或留白失衡。
   - 容器四周内边距充足，首屏核心内容（如 2×2 技能拆解网格）应在标准视口内一屏完整呈现。
2. **对齐与等高**：
   - 双栏/多栏并排卡片（如 Bento Grid、A/B 方案对比）同行高度必须严格齐平（`align-items: stretch`）。
   - 表格与指标行的标题列、数值列、胜出胶囊必须垂直对齐，严禁因字数不同导致列宽左右摇摆。
3. **排版与防截断**：
   - 正文字号 `≥12px`，次级说明/徽章 `≥10px`。
   - 必须测试超长文本边界（如 `元流之子(坦克)`、复合被动词条）：通过自适应字号或主次双层拆行完整展示，**严禁出现半截省略号 (`...`)、文字溢出边框或尴尬的单字折行**。
4. **色彩与视觉层级**：
   - 保持 Apple 极简克制风格：大背景浅灰白 (`#f5f5f7`)、卡片纯白 (`#ffffff`)、边框微透；严禁大面积高饱和度色块堆砌。
   - 强调色仅用于关键胜出方（方案 A 蓝 `#0071e3`、方案 B 绿 `#1b6d2f`）与核心状态胶囊，主次指标字重与颜色深浅分明。
5. **静态资源与交互可用性**：
   - 逐一检查头像、装备、技能与普攻图标是否 100% 正常渲染（无破图、无错误默认占位图）。
   - 验证分路切换、弹窗开关、筛选 Tab 与 URL 参数跳转逻辑正常无阻断。

## 三、 强制闭环流程
`修改代码` → `python build.py 同步产物` → `Playwright 截取常规态+边界态（如输出位+游走位）` → `view_file 视觉自审` → **发现任何瑕疵立即自行回炉修正并重新截图核验** → `视觉完全达标后清理临时文件并交付用户`。
